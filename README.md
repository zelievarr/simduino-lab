# SIMduino lab — лаборатория Arduino Uno

Рабочая первая версия симулятора для занятий. Независимый проект: не использует очередь, компилятор, учётную запись или подписку Wokwi.

## Открыть на этом Mac

Компилятор и ядро Arduino Uno установлены в `.tools/` этого проекта.

1. Дважды нажмите **Запустить SIMduino lab.command**.
2. Откройте **http://127.0.0.1:4173**.
3. Изменяйте `sketch.ino`, нажмите **Запустить**. Терминал оставьте открытым.

Если сервер уже запущен, просто откройте ссылку. Остановка: Ctrl+C в его терминале.

## Что действительно работает

- Настоящая сборка Arduino C++ через официальный Arduino CLI / AVR GCC на своём компьютере.
- Настоящее выполнение ATmega328P через AVR8js в Web Worker. Частота 16 MHz, GPIO, timers/PWM, ADC, USART, EEPROM в течение сеанса.
- 11 моделей: Uno, LED, RGB LED (общий катод), резистор, кнопка 12 мм, кнопка 6 мм, переключатель, потенциометр, слайдер, сервопривод, пьезодинамик.
- Перетаскивание компонентов, соединение выводов, цвета проводов, масштаб и панорамирование, удаление соединений, undo/redo схемы, цвет LED и сопротивление.
- CodeMirror: C++-подсветка, номера строк, история кода, Tab-отступы, скобки.
- Монитор Serial (приём и отправка), настоящие ошибки компиляции, уведомления и отключаемый звук успешного запуска. Ошибка сопровождается встряхиванием и крупной надписью; успешный запуск — фейерверками слева и справа. При настройке reduced motion движение отключается.
- Подсветка краёв окна следует яркости и цвету работающих LED и RGB LED; цвета нескольких светодиодов смешиваются.
- Семь скомпилированных примеров: Blink, светофор, кнопка, Fade, потенциометр, мелодия, сервопривод без внешних библиотек.
- Автосохранение в браузере, именованные проекты, экспорт/импорт `.simduino.json`, импорт `.hex`.

## Границы версии 0.1

**Это ещё не полная замена Wokwi.** Каталог содержит 85 записей по официальной странице supported hardware, включая семейства/варианты плат. Только 11 помечены рабочими; остальные видны как «В разработке» и не добавляются как якобы работающие модели. Периферия I²C/SPI/OneWire, датчики, дисплеи, макетная плата, ESP32 и другие процессоры ещё не реализованы.

Резисторы участвуют в логической связности. Аналогового SPICE-расчёта напряжений, токов, нагрева, RC-цепей и повреждений нет. АЦП моделирует значения потенциометра при подключении VCC и GND. Есть проверка прямого замыкания питания на землю и предупреждение о LED без резистора. Это не проверка безопасности физической схемы. Частота эмуляции зависит от мощности устройства.

**Опубликованная статическая веб-версия** исполняет готовые прошивки семи примеров и импортированные Intel HEX. Произвольный изменённый C++ компилируется только при запуске **локального сервера** или собственной Docker-версии. Статический хостинг Sites не запускает нативный AVR GCC. Приложение явно сообщает об этом, код пользователя не заменяется готовым примером.

Сохраняются код и схема, без прошивки, состояния RAM и EEPROM. HEX привязан к сеансу и сбрасывается при редактировании кода. В файле проекта — формат SIMduino lab, не полная совместимость с `diagram.json` Wokwi.

## Для одногруппников по локальной сети

На компьютере преподавателя/студента с Node.js 22+:

```sh
HOST=0.0.0.0 node server.mjs
```

Остальные открывают `http://IP-ЭТОГО-КОМПЬЮТЕРА:4173` в одной Wi-Fi/LAN сети. Каждый хранит проекты у себя в браузере. Компиляция выполняется на компьютере сервера (до четырёх параллельных сборок, без искусственной очереди). Сервер должен оставаться включённым. Сетевой режим не включён автоматически; по умолчанию сервер слушает только `127.0.0.1`.

Для отдельного сервера есть Docker:

```sh
docker build -t simduino-lab .
docker run --rm -p 4173:4173 --memory=1g --cpus=2 simduino-lab
```

Используйте в доверенной учебной сети. Перед открытием компилятора в публичный интернет нужны отдельная изоляция каждой сборки, аутентификация и ограничения запросов. Dockerfile предназначен для учебного развёртывания, не для недоверенных публичных пользователей.

## Установка на другом компьютере

Готовая папка `dist` уже собрана. Для локального компилятора на macOS/Linux:

```sh
node scripts/setup.mjs
node server.mjs
```

Скрипт загружает официальный Arduino CLI и ядро `arduino:avr` в `.tools/`. Первичная установка требует интернета. После установки компиляция не обращается к Wokwi.

## Разработка и проверка

```sh
pnpm install --ignore-scripts
node scripts/build.mjs
node scripts/compile-examples.mjs
node --test tests/circuit.test.mjs tests/simulator.test.mjs
node server.mjs
```

При изменении примеров пересоберите `dist/firmware.json`. В `server.mjs` список разрешённых заголовков; библиотеки надо установить через Arduino CLI и добавить в этот список. Servo.h и LiquidCrystal.h устанавливаются скриптом setup. Пример сервопривода использует прямые импульсы; драйвер также декодирует импульсы Servo.h. LCD-модели пока нет.
